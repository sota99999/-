# 新・予想モデル設計（作り直し版）

## 全体像
予想は次の6要素で構成する。ベースは「馬の能力」。

1. **馬の能力**（瞬発力・持続力・トップスピード・パワー・スタミナ・スタート）
   — 全ての基礎。適性/展開が向かなくても能力で勝ち切ることがある。
2. **コース適性**（中山=パワー、東京=長い直線、函館=小回り洋芝短直線 …）
   — course_master / v_course で実装済み。格上逆転の要因。
3. **距離適性**（スタミナ、追走力）— 距離が長くスタミナ不足なら大きく減点。
4. **道悪適性**（良 or 道悪の2択でよい）— 苦手なら大きく減点、得意なら格上逆転。
5. **レース展開**（前半: ハイ/ミドル/スロー × 後半: ラスト2F瞬発力戦 / ラスト3〜5Fロングスパート戦）
   — トラックバイアス・脚質と絡む。course_masterのpace_bias＋race_lapsで推定。
6. **斤量**（1kg=0.1秒。牡牝2kg、3歳/4歳上2kg差が基本）。

## STEP1（今回）: 展開・斤量を補正した「1走の実力値」= v_run_adj
過去の教訓: 最高SP(天井)は"まぐれ図"に汚染される（宝塚記念のマイネルエンペラー131.5→10着）。
そこで**1走ごとに展開と斤量を補正した quality_sp** を作り、これを能力の素点にする。

- `sp` = スピード指数（v_speed。同条件相対タイム）
- **斤量補正** `sp_wadj = sp + (weight_carried − レース平均斤量) × 0.8`
  （重い斤量で出した時計は価値が高い。0.1秒≈0.8指数 換算）
- **展開補正** `trip_adj = clip(1.2 × (0.5 − pos) × pace_fast, ±3)`
  - `pos` = その日の隊列（最初のコーナー通過順/頭数。低い=前）
  - `pace_fast` = 前半3Fが基準より速いほど＋（ハイ）、遅いほど−（スロー）
  - 前(pos小)×ハイ(pace_fast＋)=厳しい流れを粘った→加点／前×スロー=楽逃げ→減点／
    後(pos大)×ハイ=展開に恵まれた差し→減点 …という直感を式化。
- **quality_sp = sp_wadj + trip_adj** ← これが「展開・斤量ニュートラルな1走の実力」

同時に、後段の能力分解に使う素点も1走ごとに持たせる:
- 瞬発力: `last_3f`（上がり3F。小さいほど鋭い）
- 持続力: 前傾ラップ（ロングスパート）での quality_sp
- トップスピード: 良馬場での quality_sp
- パワー: 急坂コース(hill_grade='steep') or 道悪 での quality_sp
- スタミナ: 長距離(mid/long)での quality_sp
- スタート/先行力: `pos`（隊列を取れているか。枠との関係は後で）

## STEP2（次回）: 6能力への集約 = v_ability（リーク防止の窓集計）
各馬×各レース時点で「その馬の過去走だけ」から6能力を作る（features.sql と同じ
`ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING` 窓）。凡走は無視し**好走時(3着内)**中心。

- power_top = 好走時 quality_sp の高位（安定した実力。天井でなく好走平均ベース）
- shunpatsu = 好走時 last_3f の速さ（瞬発力）
- jizoku    = 前傾/ロングスパート好走時の quality_sp（持続力）
- stamina   = 長距離好走の quality_sp・複勝率
- power     = 急坂/道悪好走の quality_sp・複勝率
- start     = 平均 pos（先行力）
※「最低好走数」ガードで小サンプル吊り上げ（好走平均⭐の罠＝ビザンチン118.3）を防ぐ。

## STEP3: 適性・展開・斤量を予想時に掛け合わせ（= v_predict）
検証（全期間・クラス別に power_top と頭合わせ）で得た結論を反映済み:

| 掛け合わせ項 | 検証結果 | 採否 |
|---|---|---|
| 斤量 weight_adj | 未勝利 top1 0.246→0.117 と半減（下級の斤量は年齢/牝馬/見習い＝軽い程弱い） | ❌ 撤去 |
| 展開 trip_adj | 全クラス悪化（未勝利 0.708→0.345）。脚質ノイズが能力を上書き | ❌ 非加算(参考メモ) |
| コース course_adj | 集計で僅かにマイナス（能力が既にコースを織り込む） | ⚠️ 非加算(参考メモ) |
| 距離 dist_adj | 中立〜微増（スタミナ不足の減点として理論整合・無害） | ✅ 採用 |
| 道悪 off_adj | 全クラスで僅かにプラス（唯一効く適性） | ✅ 採用 |

**最終形: `predict = power_top + dist_adj + off_adj`**（下級を壊さず 2勝・重賞で微増）。

### なぜ掛け合わせが効かないか（重要な学び）
展開・斤量は **STEP1 の quality_sp で1走ごとに既に補正済み**。予想時にもう一度
足すと**二重計上のノイズ**になる。適性も power_top が「好走時 quality の平均」で
その馬の得意条件を既に反映するため、上乗せは平均的には無効。
→ 展開・斤量・適性は「**過去の実力を測る(STEP1/2)**」で活き、天井SP撃破の主因に
なった。「**今日を予想する(STEP3)**」では距離・道悪ペナルティのみが僅かに効く。
course_adj / trip_adj は人間の最終判断用の**参考メモ**として列に残す。

## 検証方針（実施済み）
各ステップを全期間・クラス別に **天井SP / power_top と頭合わせ**し、
「未勝利(下級)を壊さず、重賞・OPで改善するか」を確認して採用した。
- STEP2 power_top: 天井SP を全クラスで撃破（未勝利 top1 0.516→0.710、重賞も改善）。
  宝塚記念2026 の実1〜3着を power_top 順で 1・2・3 に的中。
- STEP3 predict: 下級 非劣化、2勝・重賞で微増。

## STEP4: 相対R（毎レース全馬を相対評価する主軸指標）= compute_relative_r.py
power_top（時計系）は「スピード指数がクラス＝相手の強さを見ない」弱点があり、
弱い平場で好時計の馬を過大評価し、スロー質のG1を勝った実力馬を過小評価する
（大阪杯2026 で顕在化）。Elo も圧縮されすぎて格差を作れない。

そこで **反復 strength-of-schedule レーティング（相対R）** を導入:
`perf_i = 出走全馬の平均R + SPREAD×(0.5-(着順-1)/(頭数-1))` を収束まで反復し、
シーズン全体の勝敗ネットワークから「強い相手を負かした馬」を上に開く。
リーク防止は月次スナップショット（当該月より前の結果だけ）で `r_before` を付与。

### 検証結果（リーク防止版・全期間クラス別）
- **相対R は top3複勝率で全クラス優位**（重賞級 0.352→0.396、複勝/BOX の軸）。
- power_top は 未勝利・重賞の **top1** で優位（若駒はネットワークが薄い）。
- **線形ブレンドは有害（U字）** → 融合せず 2指標を併記する。
- 大阪杯2026: 相対R上位に ダノン(3着)・クロワ(1着)、時計上位のデビット(8着)は後退。

### 最終カード（scripts/card.py --ability-only）
元の2指標（最高SP＋Elo）を格上げした形:
- **主軸 = 相対R**（格・対戦）… 相対R順に並べ、複勝/BOXの軸。
- **相補 = power_top**（時計・能力）… 単勝1点・未勝利の補完。
- 融合値は作らない。各指標に ⭐◎○▲△・✅。**両方で高い馬が本命級**。
- 9分類回顧（ability_eval.py）も 相対R×power_top に置換。

### 週次パイプライン
collect後: `compute_ratings.py`（Elo）→ `compute_relative_r.py`（相対R）→
`features.sql`/`course_master.sql`/`ability.sql` 適用 → `card.py --ability-only`。
